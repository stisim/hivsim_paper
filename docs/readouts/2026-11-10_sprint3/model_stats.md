## Notes

- **How measured:** `/usr/bin/time -v` around one process per run (elapsed wall time, maximum resident set size), Python with one thread (`NUMBA/OMP/MKL_NUM_THREADS=1`), env `hp_rc3` with Starsim `/tmp/ss-nov09` (f1273734) and STIsim `/tmp/sti-613` (ebbc8e7); Optima in env `optima`. Times include Python start-up, imports and building the sim. For HIVsim, the hybrid and Optima a first warm-up run (Numba compiles and caches) is logged as `r0` and not counted.
- **"Alone":** the 3 EMOD binary runs ran at the same time as each other, and the Python models in 4 lanes side by side, on 160 cores otherwise idle (another agent's 150-process job had just finished) — except for the third Optima′ agents run (149 s), which overlapped about 20 processes of another job. A first pass during a 150-process job was 1.8–4× slower (HIVsim 47 s, EMOD 372 s, kept in `logs/contended/` for EMOD) and was discarded.
- **EMOD binary:** set 0, seeds 1–3, on analysis 18's `fig3a_both` inputs (PR #4's mortality and dropout fixes), with its transmission reports on (as analysis 18 runs it); copied to `/tmp/hp-ro-stats-emod/`. Without the transmission reports it is probably somewhat faster (not measured).
- **EMOD′:** `harness.make_sim(pid=0, seeds 1–3, hiv=True, cascade=True, condensed=True, fixes=('mortality', 'reenrol'))`, i.e. `emod_fixed` with the condensed cascade, from 1960.5 in one go. The burn-in column is the time from start to reaching 1985 within that run (the runner saves the burn-in there and resumes from it, so a resumed run costs about 43 − 9 = 34 s). Its line count includes the alternative cascades (interpreted, compiled), the variants and the harness; `adapters.py` (swap only) and tests are excluded.
- **HIVsim:** `swap.make_sim('own', n_agents=10e3, stop=2025)` with `models/hivsim/reference/pars.json`. Its 266 lines are this repo's Malawi set-up; the model is STIsim.
- **Optima:** `P.runsim('20220912', end=2025)` on `Malawi_20220912.prj` (load 0.6 s, run 1.1 s). Optima′ ODE: `optima_prime.make_sim(components=all six, dt 0.02)`. Optima′ agents: `agents.make_sim(n_agents=100_000)`. Most of Optima′'s time is per step (1,482 compartments, 1,750 steps at dt 0.02, 10× Optima's steps); init (building the sim) is 22–23 s of each run, not broken down here.
- **Hybrid:** analysis 16's `HHEE` (fixed): `swaps.build({D: hivsim, RN: hivsim, V: emod_fixed, C: emod_fixed})`, cells p0_s1–s3. D is HIVsim's, so no burn-in.
- **Against recorded times** (`docs/swap_design.md` §4): HIVsim 10 s to 2021 then, 11 s to 2025 now; EMOD′ condensed 74 s then (30 at once), 43 s now alone; Optima′ agents 180 s to 2021 (analysis 20), 140 s to 2025 now. Analysis 16 recorded 14–16 s per hybrid with 100 at once.
- **Lines of code:** non-blank, non-comment Python lines (`measure_stats.py loc`, `logs/loc.json`; `cloc` isn't installed). Optima′ excludes `acceptance.py` and `compare.py` (checks).
- **Fidelity** numbers are cited, not re-measured: analyses 04, 06, 11, 16, 17, 18, 20 and `docs/optima_prime_plan.md`. Analysis 19: neither our Optima project nor Optima′ reproduces the published Optima panel (different calibration).
